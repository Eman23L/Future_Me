# How To Work With Codex On FutureMe

Before making changes, Codex should:

1. Read `docs/knowledge/futureme-current-state.md`.
2. Read `docs/knowledge/futureme-product-vision.md`.
3. Read `docs/knowledge/futureme-whats-next-engine.md`.
4. Read `docs/knowledge/futureme-next-actions.md`.
5. Read `docs/loops/active-loop.md`.
6. Read relevant architecture/rules docs.
7. Make one focused change.
8. Preserve approved UI unless explicitly told otherwise.
9. Run `npm run build`.
10. Run `npm run test:scheduler` if available.
11. Update docs if decisions changed.
12. Summarise changed files.
13. Commit and push only when asked or when the workflow requires it.

Codex should not ask the user to re-explain FutureMe from scratch. Use the repo knowledge base first.
