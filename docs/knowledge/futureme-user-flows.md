# FutureMe User Flows

## Core Flow

1. Welcome screen.
2. Setup.
3. Monthly fixed commitment input.
4. Work patterns.
5. Appointments.
6. Deadlines.
7. Social plans.
8. Wake-up and bedtime.
9. Flexible activity toggles.
10. Capacity page.
11. Notification vibe.
12. Generated schedule.
13. Daily dashboard.
14. What’s next view/current task.
15. Completion tracking.
16. Enable reminders.
17. Add to Home Screen.
18. Push notification permission flow.
19. Optional notification nudges.

## Planning Inputs

The user gives FutureMe the anchors of the month: fixed commitments, sleep boundaries, routine preferences, and capacity. FutureMe should not require perfect data to be useful.

## Generated Schedule

FutureMe uses fixed commitments first, then places flexible activities around rules, sleep, capacity, and conflicts. The generated plan should feel like a supportive draft of the month, not a rigid command.

## Daily Dashboard

The user should open the app and immediately understand what is next. The daily dashboard is more important than the notification layer.

The dashboard should show:

- Current task.
- Next task.
- Upcoming tasks.
- Overdue tasks.
- Completed tasks.
- A clear daily focus.
- Gentle reschedule or recovery guidance when needed.

## Notification Flow

Reminders are optional nudges. The user may install the PWA, enable notifications, and receive push reminders, but FutureMe must still work without them.

Notifications should point the user back to the app. They should not become the source of truth for task state.
